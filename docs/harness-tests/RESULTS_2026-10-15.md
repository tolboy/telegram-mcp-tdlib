## Hermes

The model used native `telegram_baratnor` tools, verified the intended account,
and observed the connected manifest's 35-tool read-only inbox surface. It read
a prefix of 20 recent chats, two unread conversations and five distinct messages
per conversation, including a second older page. Content and partial-coverage
flags were visible. The digest explained that coverage was truncated and did
not treat general group questions or another username's mention as personal
requests. The deliberate blank-identifier call produced the intelligible
`Identifier must not be blank` error; the model did not observe an `isError`
flag or structured error code in the host's presentation. No Telegram writes
were requested. The anonymized report is `build/harness-reports/hermes-ui-test.json`.

This tests the dirty local server version `1.17.0-1-g5b712c9-dirty` and explicit
reading of skill instructions. Automatic skill discovery, Agensi delivery,
fresh authorization, text-only fallback and lifecycle recovery remain untested.

## Cursor

The existing Unity entry was preserved while adding the daemon entry. Cursor's

## Claude setup

Claude Desktop is the Windows Store application 2.19675.0.0, ordinary Chat with
Sonnet 5.5 Medium. Its cloud execution sandbox cannot read local Windows files;
the complete COMMON.md and SKILL.md were therefore pasted into the existing
test chat. The obsolete `telegram-demo` entry was backed up privately and
replaced with `telegram_baratnor`, a private local STDIO-to-HTTP tools proxy
using the already installed Python MCP SDK 1.22.0. The proxy forwards tools and
CallToolResult content/structuredContent/isError without starting TDLib.

A separate SDK check through the proxy observed 35 tools, the expected identity,
and `isError=true` with the blank-identifier error. This is auxiliary evidence,
not a Claude model pass.

Closing Claude's window left the old process and catalog alive; File -> Exit
was required before relaunch. The first bridge launch then failed because
Windows Store AppData virtualization made Codex's apparent local script path
unavailable to Claude. The log reported “can't open file ... No such file or
directory”. Changing the entry to the resolved physical script path fixed that
launch failure: Claude's log recorded initialize, initialized and tools/list.
No credentials were copied into chat or repository files.

After the corrected restart, Claude used the new native connector and reported
PASS_NATIVE: the manifest's complete 35-tool list excluded write/download tools,
identity matched, and two pages per conversation yielded five distinct messages
each within the 20-chat/two-conversation budget. The Russian digest stated
coverage and uncertainty without treating an ambiguous group question as an
explicit personal request. The deliberate blank-identifier error was intelligible
and was not repaired or retried. Content and truncation/cursor fields were visible
as JSON text; raw content blocks, annotations, structuredContent and isError
were not observed by the model. This is not a text-only-fallback test.

The model conservatively could not distinguish client validation from the server
parser using the error text alone. Auxiliary operator evidence resolves that
origin: the bridge disables input validation, and Claude's transport log records
the tools/call request id=9 and its returned result at 14:35:47 UTC. The separate
SDK proxy test observed isError=true; this does not make that flag visible to
the model. The copied anonymized JSON plus this corroboration is saved at
`build/harness-reports/claude-ui-test.json`.

Only per-call “Allow once” tool approvals were used. No persistent tool approval,
subscription, billing or Telegram-state change was made. Client app restarts
were setup actions; daemon restart/reconnect and termination recovery were not
tested. The daemon retained PID 6340 throughout these desktop runs.

Two observations merit review before distribution: the manifest's routing hints
still mention unavailable write tools, although its actual catalog hides them;
and get_me supplies the account's phone/profile fields to the model even though
the skill does not need them. The reports omit these private fields. Neither
observation caused result parsing or read-only policy failure in these runs.

These are local environment and connection-path observations. They do not
certify other Claude surfaces or the marketplace's full client list.
